Offer-style integration targets use this shape:

```hcl
{
  kind     = "endpoint" # or "offer"
  name     = optional(string)
  endpoint = optional(string)
  url      = optional(string)
}
```

Use `kind = "endpoint"` with `name` and `endpoint` for same-model relations. Use `kind = "offer"` with `url` for cross-model relations.

### Sensitive configurations and secrets

S3 and GCS credentials are sensitive, ephemeral inputs. Juju secrets use write-only `value_wo` values, keeping credentials out of state and saved plans. Supply them through `TF_VAR_s3_access_key`, `TF_VAR_s3_secret_key`, or `TF_VAR_gcs_secret_key` at plan and apply. Passing credentials through `-var` may expose them in shell history; avoid credential `.tfvars` files. Forwarding root modules must also declare their credential inputs sensitive and ephemeral.

| Credential inputs                | Version              | Existing URI     | Secret keys                         |
| -------------------------------- | -------------------- | ---------------- | ----------------------------------- |
| `s3_access_key`, `s3_secret_key` | `s3_secret_version`  | `s3_secret_uri`  | `access-key`, `secret-key`          |
| `gcs_secret_key`                 | `gcs_secret_version` | `gcs_secret_uri` | `secret-key` (service-account JSON) |

| Version         | Credential | Result                           |
| --------------- | ---------- | -------------------------------- |
| `0` (default)   | unset      | No managed secret                |
| `1`             | set        | Secret created, revision 1       |
| `2`             | new value  | In-place rotation, revision 2    |
| `2` (unchanged) | unset      | No secret update                 |
| `0` again       | unset      | Managed secret and grant removed |
| `1` again       | set        | New secret, revision 1           |

Configure the matching `backups_integrator.storage_type` before setting a nonzero version. Both S3 keys share one version. Keep versions in non-sensitive configuration. To rotate, change the credentials and increment the matching version together. Changing credentials alone has no effect. Unrelated plans and applies work with credentials unset.

An existing-secret URI overrides credentials and version. The module creates no secret, grants the matching integrator access, and passes the URI through its `credentials` config. It must exist in that integrator's model and contain the keys listed above. Both `secret:<id>` and `secret://<model-uuid>/<id>` are supported. Secrets are used only when the matching integrator is enabled.

When switching from a managed secret to a URI, use a separate existing secret: Terraform destroys the previously managed secret. The supplied secret's contents and lifecycle remain externally managed.
